# StudentTournamentKit (STK)

Платформа для **дистанционных турниров по CS2** (5×5) с полупрофессиональной трансляцией: игровой сервер, судья, режиссёр, overlay, комментаторы, запись матча.

Продукт **нейтральный** — не привязан к университету или конкретному медиа. Репозиторий: `BestCSTournaments`.

---

## Зачем это

Организатор проводит удалённый турнир без «склейки» из разрозненных чатов и скриптов.  
Режиссёр ведёт эфир с **одного ноутбука** (игра + OBS + панель).  
Судья с телефона запрашивает проверку → система ставит техпаузу → продолжает или засчитывает поражение.  
Зрители смотрят стрим (обычно Twitch) с задержкой; на overlay — едва заметный watermark платформы.

## Кто пользуется

| Роль | Что делает |
|------|------------|
| Организатор | Турниры, команды, матчи, брендинг |
| Режиссёр / оператор | Сцены OBS, overlay, камера, эфир |
| Судья | Проверка, пауза, forfeit или продолжение |
| Комментаторы | Видео из браузера (1–2 человека) |
| Игроки | Подключаются к CS2 на VPS |

## Как устроено (простыми словами)

```text
Игровой сервер CS2  ←→  Платформа (API + база)  ←→  Панели в браузере
         ↑                        ↑
   плагин / Fake-сервер     режиссёрский ноутбук (OBS)
```

Платформа — источник правды по матчу (счёт, статус, решения судьи).  
Игровой сервер шлёт события и принимает команды (пауза, продолжение, forfeit).  
Запись демоматча сохраняется так, чтобы не пропасть только «на диске сервера».

Подробнее: [overview/product.md](overview/product.md) · [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Как проверить локально (кратко)

1. Скопировать `.env.example` → `.env` (если ещё нет).
2. Поднять MySQL через Docker Compose (`infra/platform/`).
3. Запустить API из `apps/api/`.
4. Прогнать проверку:

```powershell
pwsh -File scripts/verify.ps1
```

Smoke для Game Slice (Fake CS2): [workers/developer/notes/TZ002-OWNER-SMOKE.md](workers/developer/notes/TZ002-OWNER-SMOKE.md).

Живой CS2: локальный DS @owner — [`infra/game-server/LOCAL-CS2-DS.md`](infra/game-server/LOCAL-CS2-DS.md) (`Z:\cs2_dedicated_server\…`). Ubuntu VPS — [`infra/game-server/README.md`](infra/game-server/README.md).

## Как ведётся разработка (ИИ-агенты)

Большую часть кода, тестов, контрактов и документации в этом репозитории пишут **ИИ-агенты в Cursor** — по ролям (Team Lead, разработчик, тестировщик, DevOps, документалист и др.), с общей памятью в `workers/` и ТЗ в `tasks/`.

Владелец задаёт цель и принимает решения; агенты выполняют срезы по промптам, обновляют журналы и не коммитят секреты.  
Это осознанный способ разработки: вертикальные срезы, ясные критерии готовности, проверка `scripts/verify.ps1`.

Как устроена команда агентов: [AGENTS.md](AGENTS.md) · принципы: [PHILOSOPHY.md](PHILOSOPHY.md).

Коммиты в git — только по решению владельца (`@owner`).
